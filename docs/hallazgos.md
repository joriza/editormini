# Hallazgos del proyecto

Lo que el análisis y el desarrollo fueron dejando: hallazgos de ingeniería inversa, defectos encontrados (y su lección), y decisiones con dato.

## 1. Ingeniería inversa de los editores de referencia

Método: CLI de REA v6.4.0 (`inspect-artifact` para identidad PE con digest), sondeo de cadenas del binario, y el `.pdb` incluido en la distribución de MS Edit. Ghidra no estaba configurado en esta máquina (requiere descarga de 12.1.x + addon nativo de Windows de REA sin construir); como ambos editores son open source, se decidió correlacionar binario + fuentes públicas en lugar de decompilar.

### micro 2.0.15 (referencia de Go)

- Go 1.23.12 + **tcell** + **gopher-lua** (plugins en Lua), símbolos Go visibles en el binario.
- Lecciones para editormini: keymap centralizado, sistema de comandos, plugins como extensión.

### Microsoft Edit 2.0.0 (referencia de Rust)

El `.pdb` entregó la arquitectura interna completa:

- **TUI propia**: `tui.rs`, `framebuffer.rs`, `input.rs`, `vt.rs`, `cell.rs` — no usan ratatui/crossterm; construyeron su propio framebuffer VT. Confirma que el techo de rendimiento en TUI está en controlar el render fino (nosotros llegamos antes con ratatui y podemos bajar de nivel después).
- **`gap_buffer.rs`**: el texto vive en un gap buffer, no en rope ni en Vec de líneas. Validó nuestra decisión de aislar el almacenamiento detrás de una API estable para cambiarlo sin tocar la UI.
- **`lsh/`** (resaltado con definiciones generadas), **`fuzzy.rs`** (buscador difuso), separación de dibujo en `draw_menubar/draw_editor/draw_statusbar/draw_filepicker`, localización integrada, SIMD para escaneo de líneas.
- CLI `edit [FILE[:LINE[:COLUMN]]]` — patrón adoptado para nuestro soporte multi-archivo.

## 2. Defectos encontrados y su lección

| Mensajes de estado efímeros | "Ctrl+S no parecía grabar" | El status se limpiaba en cada frame: "Saved" duraba un parpadeo | El mensaje persiste hasta la próxima acción de edición | El feedback que no se alcanza a leer es equivalente a no tener feedback |
| Guardar sin destino | Guardar un documento sin título no hacía nada visible | Documento sin ruta + error invisible por el punto anterior | Error persistente en pantalla; (Guardar Como llega en el hito de ciclo de archivos) | Nombrar el destino antes de prometer el guardado |
| `Ctrl+S` "no llegaba" | En Git Bash/mintty el guardado no respondía | **Control de flujo del terminal**: mintty consume Ctrl+S (XOFF) antes de que llegue a la app | `F2` como guardado universal + recomendación de Windows Terminal en README | En TUI, toda tecla crítica necesita una alternativa inmune al terminal |

| Doble coma en catálogo i18n | Errores fantasma de compilación en otro archivo | Un error de sintaxis en `i18n.rs` dejaba `Lang` sin resolver y cascadaaba a `config.rs` | Fix de la coma | Un defecto de sintaxis puede disfrazarse de error semántico en archivos vecinos |
| Assertions rotas en tests por migración i18n | 3 tests fallían tras la migración i18n del diff preexistente | Las assertions usaban `i18n::t(Lang::En, Key::FileOpened)` (que retorna `"Opened {path}"`) en `contains()`, pero el status real tiene la ruta sustituida, no el placeholder | Reemplazar por `starts_with(&i18n::t(...).replace("{path}", ""))` para verificar el prefijo sin placeholder | Los tests de integración con strings traducidas deben verificar el prefijo estático, no la plantilla con placeholder |

## 3. Aprendizajes de proceso

- **Falsos positivos del chequeo de diagnósticos de sesión**: reportó varias rondas un `Lang: Default` inexistente en `config.rs`. Se desmintió con dos autoridades: el compilador (`cargo check`, para quien un trait bound sin satisfacer es error de compilación) y sondas LSP frescas (`source=lsp`). El cache de sesión se sincronizaba recién después de nuevas escrituras. Lección: ante desacuerdo entre cache y compilador, el compilador manda; documentar y seguir.
- **Delegación a subagentes**: `gentle-ai-worker` rechazó la admisión dos veces ("Writer session Git authority changed before admission"). Se aplicó el plan B de la escalera de ruteo (implementación inline) sin bloquear el trabajo. **Actualización**: tras reiniciar Pi con el repo ya existente, `gentle-ai-verify` y `gentle-ai-worker` admiten y completan sin fricción; la delegación volvió a ser la ruta por defecto.
- **Autoridad de review**: el ciclo de revisión formal (RDD) no pudo inicializarse porque la autoridad Git de la sesión cambió a mitad de camino (el repo se creó durante la sesión). El candidato quedó declarado **sin revisión formal**; la verificación efectiva fue la red de tests + prueba interactiva del dueño. Re-abrir la sesión con el repo ya existente habilita la revisión formal si se desea.
- **Falso positivo del revisor nativo sobre Rust moderno (tarea 8)**: la revisión formal del commit `d13f07c` corrió la lente `review-reliability`, que produjo el hallazgo BLOCKER R3-001: "`let ... else` no es Rust válido; fallaría la compilación". Es falso: let-else es estable desde Rust 1.65, el toolchain local es 1.99, y `cargo build` pasa con 0 warnings + 78 tests verdes. La admisión nativa degradó el hallazgo (`unverified_location`) pero la causalidad `unknown` escaló el linaje a stop terminal (`native_stop_required`), que es definitivo para ese candidato: la entrega queda decidida por la política ordinaria del repo (worker self-verify + verificador independiente ya la cubrían). Lección doble: (1) el revisor del proveedor aparenta usar un modelo desactualizado respecto a sintaxis Rust post-1.65 — tratar sus BLOCKER "sintácticos" con el compilador como árbitro; (2) un stop terminal no invalida el trabajo: es informativo y no autoriza ni bloquea la entrega.
- **Ronda de hardening task 9 (mouse)**: hallazgos informativos del revisor nativo sobre el candidato d44df3c aplicados como ingeniería ordinaria: (1) refactor `tab_layout` helper compartido entre render y `tab_at_column` para eliminar duplicación de layout, (2) test de `col_off` no nulo en clic con scroll horizontal, (3) tests de rueda de scroll afinados para assertar distancia exacta (`viewport_h - 1`) y clamping en límites. para el commit `9742ccc`, la misma lente produjo 3 BLOCKER "deterministas" afirmando fallas de compilación (atributo `about =` con expresión runtime de clap, comas opcionales tras bloques en match, captured identifiers `{lang:?}` en format strings) — los tres válidos en Rust moderno y los tres desmentidos por `cargo build` (0 warnings) sobre el árbol congelado exacto. A diferencia del caso anterior, el proveedor exigió una corrección acotada (89 líneas diff) mapeada a esos hallazgos. Se declinó submitirla: no existe corrección honesta para hallazgos no corroborados, y ediciones cosméticas para aparentar conformidad serían teatro de revisión. El linaje quedó abierto en `correction_required` a la espera de decisión del dueño. Conclusión acumulada: dos revisiones consecutivas con falsos positivos de sintaxis → la lente nativa no aporta señal para este repo hasta que el proveedor actualice el modelo revisor; su valor actual es negativo (costo de corrida + ruido).
- **Prueba del dueño como puerta**: el criterio "pará cuando haya algo que pueda probar" detectó en uso real los dos defectos más importantes de esta etapa. El orden de tareas se ajustó para maximizar esas instancias de verificación.
- **Cierre del hilo de linajes de revisión trabados (2026-10-15)**: el dueño decidió abandonar los 6 linajes en `correction_required`; el inventario nativo de autoridad resultó vacío (0 linajes — la tienda previa al reinicio de Pi ya no existe en esta máquina), así que no quedó nada que disponer. Lección: los stops terminales de una sesión muerta no sobreviven al reinicio de la tienda; se registran y se sigue por el camino ordinario (tests + verificación independiente).
- **Fallback silencioso del mapa de scopes (ronda de revisión .md, 2026-10-15)**: los tokens cuya familia de scopes no está en el mapa curado caen al foreground base sin ningún aviso — un lenguaje puede verse "sin colores" aunque su gramática resuelva perfectamente. Lección: auditar los scopes de cada gramática nueva contra el mapa con un test de colores por familia (no basta con que la extensión resuelva); fue exactamente el caso de `markup.*` en Markdown.

## 4. Decisiones con dato

- **UTF-8 únicamente** en el hito 1, con BOM detectado y preservado: cubre el uso real; UTF-16 queda fuera de alcance explícito.
- **Fines de línea**: se preserva el del archivo; mezclados se normalizan al dominante (empate → CRLF); archivos nuevos en CRLF por ser Windows-first. Tests de ida y vuelta para CRLF, LF, mixto y BOM.
- **Archivos > 10 MB abren solo-lectura**: protege la pila de deshacer futura y la fluidez; el umbral es una constante testeada sin necesidad de fixtures gigantes.
- **12 lenguajes curados** para resaltado (Rust, Go, JS/TS, Python, C/C++, JSON, TOML, YAML, MD, HTML/CSS, XML, Shell) en lugar de las ~180 de syntect: exe chico, cobertura de uso real, extensible con gramáticas externas (camino de Typst).

## 5. Decisión de crt-static para release portable

Se añadió `.cargo/config.toml` con `rustflags = ["-C", "target-feature=+crt-static"]` para el target `x86_64-pc-windows-msvc`. Esto enlaza la CRT de MSVC estáticamente en el binario, eliminando la dependencia de `VCRUNTIME140.dll` (la DLL de la redistribución de Visual C++).

**Racionale**: el objetivo del hito 11 era un ejecutable portable único sin deps runtime. Sin `crt-static`, el binario de release importaba `VCRUNTIME140.dll`, lo que obligaba al usuario a instalar el Visual C++ Redistributable o empaquetar la DLL junto al exe. Con el flag, el exe se queda como un único binario que funciona en cualquier Windows moderno sin instaladores adicionales.

**Trade-off**: el exe crece ~102 KB (de 3.35 MB a 3.46 MB) por la CRT estática incluida. Este costo es aceptable y es el estándar de la industria para binarios portátiles en Windows (usado por herramientas como ripgrep, fd, etc.).

**Nota sobre `0.dll`**: el escaneo de imports del binario muestra `0.dll` como una entrada, que es un artefacto de `grep` matching on a null byte o cadena vacía en el PE — no es una dependencia real.
- **Corrección acotada declinada por presupuesto (búsqueda tarea 1)**: la revisión del candidato Ctrl+F produjo 3 hallazgos REALES confirmados por lectura de código (Shift+caracteres descartados en la consulta por un patrón `(Char(c), false, false)`; diálogo de búsqueda dibujado antes que las líneas sobre la misma área → quedaba tapado; las líneas con coincidencias perdían los spans de sintaxis) y 1 falso positivo (afirmaba pánico de `String::pop()` sobre vacío, que en realidad devuelve `None`). El fix íntegro sumó 275 líneas diff y el tope del slot de corrección nativa es 200: se declinó la corrección formal (recorte habría debilitado tests o fix) y los arreglos se committearon como unidad ordinaria `e49cf4e` con 3 tests nuevos. Lección: el tope de corrección premia diffs quirúrgicos — mover bloques grandes (el diálogo, ~110 diff lines solo por reubicarlo) o reescribir funciones de arriba hace inviable el camino formal; preferir fixes mínimos desde el inicio.
- **Tercera ronda de falsos positivos del revisor (Ctrl+H)**: ambos hallazgos BLOCKER afirmaban fallas de compilación (patrón de tupla en `on_confirm_key`, let-else) sobre un árbol que compila con 0 warnings y 138 tests verdes — verificados por el agente independiente antes de la revisión. Corrección declinada por la misma razón que la tarea 7; linaje `review-644353f97a079b0c` queda abierto en `correction_required`. Patrón consolidado: 4 de 6 revisiones nativas de este repo produjeron exigencias inválidas; el switch queda a decisión del dueño.
